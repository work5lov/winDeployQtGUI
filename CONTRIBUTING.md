# Руководство по участию

## Стек технологий

- **Язык**: C++17, QML (Qt Quick)
- **Фреймворк**: Qt 6.8.3+ (Core, Quick, Test)
- **Сборка**: CMake 3.21+ с Ninja или MinGW Makefiles
- **Компилятор**: MinGW-w64 11+ или MSVC 2022

## Настройка окружения разработчика

1. Установите Qt 6.8.3 через [Qt Online Installer](https://www.qt.io/download) с компонентами:
   - `Qt 6.8.3 > MinGW 64-bit`
   - `Qt 6.8.3 > Qt Quick 3D`
   - `Developer and Designer Tools > MinGW 11.2.0`
2. Установите CMake 3.21+ и Ninja
3. Склонируйте репозиторий и соберите проект (см. [README.md](README.md))

## Стандарты кода

### C++
- **Стиль**: Qt-style (классы с большой буквы, методы с маленькой, скобки на новой строке)
- **Префиксы**: `m_` для членов класса, `s_` для статических
- **Константы**: выносить в `Constants.h` (namespace `Constants::`)
- **Инклюды**: группировать (Qt → стандартная → проект), использовать `#include <Q...>`
- **Запрещено**: закомментированный код, `qDebug()` в production, магические строки

### QML
- **Именование**: camelCase для id, свойства в нижнем регистре
- **Модели**: использовать `ListModel` с явными ролями
- **Компоненты**: каждый сложный компонент в отдельном файле

### Коммиты
- Используйте префиксы: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `ci:`
- Описывайте **что** и **почта**, а не только что сделано
- Пример: `feat: добавлен индикатор прогресса сканирования дисков`

## Процесс ревью

1. Создайте feature-ветку от `main`
2. Внесите изменения, следуя стандартам кода
3. Запустите тесты: `ctest --output-on-failure`
4. Создайте Pull Request с описанием изменений
5. Дождитесь одобрения как минимум одного ревьюера

## Тестирование

- **Unit-тесты**: `Qt Test` (QTest), тесты в `/tests/`
- **Запуск**: `cmake --build build && cd build && ctest`
- **Добавление**: новый тест — новый `.cpp` файл с классом `Test*`

## CI/CD

GitHub Actions настроен в `.github/workflows/build.yml`:
- Сборка под Windows (MinGW)
- Прогон unit-тестов
- Публикация артефакта сборки
